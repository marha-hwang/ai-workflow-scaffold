# 세션 작업 기록

## Overview

커밋 메시지는 **결과만** 남긴다. 무엇을 하려다 어디를 건드렸는지, 왜 그렇게 정했는지,
어디서 막혔고 어떻게 풀었는지는 세션이 닫히면 사라진다. 세션을 여러 개 띄울수록 심하다.

**검증 산출물과 다른 산출물이다.** CI 로그·리뷰 보고서는 *검증 결과*를 모으고
이 파일은 *과정*을 모은다. 같은 것을 두 번 쓰지 않는다 — 검증 결과는 링크 한 줄로 건다.

**전역 스킬이라 프로젝트를 가리지 않는다.** 특정 스크립트·폴더가 있다고 가정하지 않는다.
필요한 것은 `git` 하나뿐이고, 없으면 사실 수집만 건너뛴다(아래 1번).

## 독자가 둘이다

| 블록 | 독자 | 답하는 질문 |
|---|---|---|
| **이어받기** | 다음 세션의 나 (몇 시간~며칠 뒤) | 지금 어디까지 됐고, 다음 줄에 뭘 하나 |
| **과정** (한 일·결정·막힌 지점) | 몇 주 뒤의 나 | 왜 그렇게 정했나, 무엇에 막혔나 |

한 파일에 두 블록을 둔다. 위가 짧고 아래가 길다 — 이어받는 쪽은 맨 위 세 줄만 읽고 일을 시작할 수 있어야 한다.

## 순서

### 1. 사실부터 뽑는다 — 기억으로 쓰지 않는다

세션이 길면 무엇을 고쳤는지 기억이 어긋난다. 파일 목록과 커밋은 **명령 출력**에서 가져온다.

```sh
git log --oneline -20          # 이 중 세션 시작 지점을 고른다
git log --oneline <시작>..HEAD
git diff --stat <시작>..HEAD
git status --short             # 커밋 안 된 것 — '이어받기' 의 상태가 여기서 나온다
```

커밋이 하나도 없는 세션이면 `git status --short` + `git diff --stat` 만으로 충분하다.
git 레포가 아니면 `기계 기록` 블록을 통째로 뺀다 — **지어내지 않는다.**

조사·디버깅만 한 세션도 기록 대상이다 — **알아낸 것이 산출물**이다.

### 2. 파일을 연다

위치는 **그 프로젝트에 이미 있는 자리를 먼저 쓴다.** 순서대로 확인한다.

| 순서 | 확인 | 결과 |
|---|---|---|
| 1 | 이미 쓰던 기록 폴더가 있나 (`docs/worklog/`, `docs/decisions/`, `notes/`, `.tickets/<slug>/`) | 그 폴더에 같은 형식으로 |
| 2 | 없고 `docs/` 는 있나 | `docs/worklog/` 를 만든다 |
| 3 | 둘 다 없나 | 루트에 `docs/worklog/` 를 만든다. 사람에게 한 줄로 알린다 |

파일 이름은 `YYYY-MM-DD-<슬러그>.md`.
슬러그는 브랜치 이름이 있으면 그것, 없으면 작업 한 줄 요약(`sso-callback`, `crawler-retry`).
**같은 날 같은 슬러그 파일이 이미 있으면 새로 만들지 않는다** — `이어받기` 블록을 지금 상태로
갱신하고, 나머지는 아래에 이어 붙인다. 이어받기는 항상 최신 한 벌만 존재한다.

### 3. 골격을 채운다

```markdown
# YYYY-MM-DD <한 줄 제목>

## 이어받기

- **상태**: (지금 무엇이 동작하는가. 화면·명령 출력·데이터로 말한다)
- **다음**: (다음 세션이 첫 줄로 할 일. 1~3개)
- **주의**: (모르고 건드리면 깨지는 것. 없으면 이 줄을 지운다)

## 한 일

- (무엇을 하려고 어디를 건드렸는가. 커밋 메시지가 이미 말하는 것은 쓰지 않는다)

## 결정

| 정한 것 | 왜 | 기각한 것 |
|---|---|---|
|  |  |  |

## 막힌 지점

- **증상** → **원인** → **해결**

## 기계 기록

<!-- 명령 출력 그대로. 해석을 섞지 않는다 -->
```
커밋:
  abc1234 …
변경:
  src/… | 12 +++---
```
검증: <있으면 한 줄 — CI 실행 URL, 리뷰 보고서 경로, 테스트 로그. 없으면 이 줄을 지운다>
```

빈 섹션은 헤딩째 지운다. 막힌 것이 없었으면 `## 막힌 지점` 을 통째로 뺀다 —
빈 헤딩을 남기면 다음에 읽을 때 "여기 뭔가 있었나"를 매번 확인하게 된다.

## 슬롯 판정 기준

| 슬롯 | 통과 조건 | 미달 신호 |
|---|---|---|
| 상태 | 관찰 가능한 형태다 — "N을 하면 M이 뜬다" | "거의 다 됐다", "대부분 동작함" |
| 다음 | 다음 세션이 **파일을 열 수 있을 만큼** 구체적이다 | "이어서 진행", "마무리" |
| 한 일 | 목적이 붙어 있다 — 무엇을 하려고 건드렸는가 | 변경 파일 목록의 재서술 |
| 결정 | **기각한 대안이 하나 이상** 있다 | 기각이 없으면 결정이 아니다 → `한 일` 로 내린다 |
| 막힌 지점 | 증상·원인·해결 세 칸이 있다 | 해결만 있는 줄. 다음에 같은 데서 또 막힌다 |

원인을 못 찾고 우회했으면 **우회했다고 적는다.** 그 줄이 나중에 같은 증상이 재발했을 때
"이미 한 번 봤던 것"임을 알려주는 유일한 근거다.

## 쓰지 않는 것

- **커밋 메시지·diff 가 이미 말하는 것** — 파일 목록을 산문으로 다시 쓰지 않는다
- **추측을 사실로** — 확인하지 않은 원인은 `추정:` 을 붙인다. 붙일 수 없으면 적지 않는다
- **검증 결과 재설명** — 게이트·테스트 결과는 링크 한 줄. 해석은 `막힌 지점` 에만
- **성과 요약체** — "성공적으로 구현했습니다" 류. 한국어 문체 스킬이 깔려 있으면 그 규칙을 따른다
- **다음에 할 만한 일 브레인스토밍** — `다음` 은 이 세션이 실제로 남긴 것만. 아이디어는 이슈·티켓으로 간다

## 마지막

```sh
git add docs/worklog/<파일> && git commit -m "docs: worklog <슬러그>"
```

**커밋 여부는 그 프로젝트 규칙을 따른다.** 기록을 커밋하지 않는 레포면 파일만 두고 끝낸다.
어느 쪽이든 **커밋은 사람이 파일을 한 번 읽은 뒤에 한다** — 틀린 상태가 기록으로 굳으면
다음 세션이 그것을 믿고 시작한다. worklog 는 문서라 대개 테스트·게이트가 잡아주지 못한다.

## Common Mistakes

- **세션 끝에 몰아서 기억으로 쓴다** → 1번(명령으로 사실 뽑기)을 건너뛰면 파일 목록이 어긋난다
- **결정 표를 전부 채우려 한다** → 기각한 대안이 없는 줄은 결정이 아니다. 비워두는 게 맞다
- **이어받기를 길게 쓴다** → 세 줄을 넘으면 다음 세션이 읽지 않고 코드부터 연다
- **CI·리뷰 결과를 옮겨 적는다** → 두 파일이 갈리면 어느 쪽이 사실인지 확인하는 비용이 생긴다
- **막힌 지점을 뺀다** → 이 파일에서 가장 값이 큰 블록이다. 잘 된 일은 코드가 이미 증명한다
